# LightTable bug hunt — 8 September 2026

This campaign exercised failures that ordinary happy-path and implementation-matching tests can miss: collisions between valid files, interruptions around durable writes, changes between planning and execution, independent pixel references, randomized interaction ordering, and sustained use.

The baseline was public `origin/main` at `f783b819c3236b6442cb1d044ef45675045309fa`. Work is isolated on `codex/bug-hunt-20260908`. The original working checkout and personal catalogs were preserved. Nothing was pushed, merged, or installed.

## Compatibility and cost

Catalog schema 6 adds complete content digests and filesystem signatures. Migration creates a verified backup before additive schema changes. The first scan backfills local originals, which requires reading their complete bytes; unchanged subsequent scans reuse verified identities. Rendering reuses an exact catalog source/path digest only when the complete filesystem signature still matches. Folder-mode enumeration uses a cached full identity or a cheap partial one, keeping bulk startup reads small; full identities still guard rendering and recovery writes. Missing legacy originals without a complete digest are retained with their edits and cannot be safely relinked by a prefix alone. Restore those originals to their previous cataloged paths before rescanning.

Older builds that only understand schema 5 will refuse a migrated catalog. Returning to an older build requires its pre-migration backup; edits made after migration are not present in that backup. This campaign migrated disposable catalogs only.

The Windows correction follows the documented [Python timestamp behavior](https://docs.python.org/3.13/library/os.html#os.stat_result.st_ctime_ns) and uses the native [FILE_BASIC_INFO ChangeTime field](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_basic_info). It opens metadata-only handles and refuses a source if its change time cannot be verified. Earlier five-field Windows signatures are backfilled on scan. POSIX signatures retain their previous format. Simulations verify the branch logic and resource ownership; they do not verify the Win32 integration or behavior on a particular Windows filesystem.

Older edit-recovery drafts and cold folder-mode library rows contain weaker identities. Matching legacy drafts remain available through an explicit partial-identity notice; confirmation uses the current complete identity to guard the write. A replacement while the dialog is open still blocks restoration. Successful recovery upgrades subsequent drafts' keys. Missing or mismatched originals retain their drafts.

## Repeatable discovery plan

The original suite passed before these failures were exercised. Its blind spots included valid files with matching prefixes, changes between separately tested operations, mask optimizations without a full-frame oracle, successful writes without interruption, and edit filters checked mainly with ordinary grading state. More tests of the same happy paths would not have exposed these cases.

1. Keep the new regressions in the normal suite. When a randomized sequence fails, retain its seed and minimized action list.
2. Expand inputs by properties that change behavior: identical prefixes with different tails, odd dimensions, empty/constant images, very long Unicode names, missing originals, and old persisted formats.
3. Place fault checkpoints between read/verify/use and stage/flush/publish/acknowledge. Assert both the intended result and preservation of prior data.
4. Compare independent implementations or independent mathematical references: full-frame versus optimized masked processing, cached versus uncached RAW pixels, and generated action sequences versus a simple state model.
5. Run visible product journeys on each supported OS and a bounded longer session before release. Record source revision, fixtures, resource history, and exact blockers separately from successful tests.

Passing this campaign does not establish that all bugs have been found. It produces concrete fixes, reusable failure cases, and explicit boundaries for the next platform pass.
